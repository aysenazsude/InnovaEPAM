# Data Model: Draft Management — Phase 4

**Branch**: `004-draft-management` | **Date**: 2026-05-14
**Source**: `specs/004-draft-management/research.md` (R-001, R-002, R-003)

---

## New Entities

### Draft

Represents a partially-completed idea owned by a submitter. All content fields are nullable — a draft may be saved in any state of completion.

| Field | Type | Nullable | Constraints | Notes |
|-------|------|----------|-------------|-------|
| `id` | `text` (UUID) | No | PRIMARY KEY | Generated by server (`crypto.randomUUID()`) |
| `submitterId` | `text` (UUID) | No | FK → `users.id` | Owner; only this user can access the draft |
| `title` | `text` | Yes | max 200 chars | Defaults to display as "Untitled Draft" when null |
| `description` | `text` | Yes | max 2000 chars | — |
| `category` | `text` | Yes | FK → `idea_categories.slug` | null = no category selected |
| `version` | `integer` | No | DEFAULT 1 | Incremented on every save; used for optimistic concurrency (R-003) |
| `createdAt` | `integer` | No | Unix epoch ms | Set on creation, never updated |
| `updatedAt` | `integer` | No | Unix epoch ms | Set on every save |

**Indexes**:
- `idx_drafts_submitter_id` on `(submitter_id)` — for "list my drafts" queries
- `idx_drafts_updated_at` on `(updated_at DESC)` — for ordered listing

**Constraints**:
- No two drafts share an `id` (PK)
- `submitterId` references a valid user
- At most 10 draft rows per `submitterId` (enforced at the application layer inside a transaction — see R-005)

---

### DraftCategoryData

Stores the category-specific field values for a draft. Mirrors the `idea_category_data` structure. Separate table to keep `drafts` lean and avoid wide nullable columns.

| Field | Type | Nullable | Constraints | Notes |
|-------|------|----------|-------------|-------|
| `draftId` | `text` (UUID) | No | PRIMARY KEY, FK → `drafts.id` CASCADE DELETE | One-to-one with `drafts` |
| `category` | `text` | No | — | Denormalised for query convenience |
| `fields` | `text` (JSON) | No | — | `Record<string, string \| null>` — category-specific field values |
| `createdAt` | `integer` | No | Unix epoch ms | — |

**Notes**:
- Row is upserted (INSERT OR REPLACE) on every draft save when category fields are present; deleted if category is cleared.

---

### DraftAttachment

Represents a file uploaded and associated with a draft. Mirrors `attachments` but references `drafts.id`. On draft submission, rows are promoted to `attachments` without file movement on disk (R-002).

| Field | Type | Nullable | Constraints | Notes |
|-------|------|----------|-------------|-------|
| `id` | `text` (UUID) | No | PRIMARY KEY | `crypto.randomUUID()` |
| `draftId` | `text` (UUID) | No | FK → `drafts.id` CASCADE DELETE | — |
| `fileName` | `text` | No | — | Original user-facing filename |
| `fileType` | `text` | No | — | Detected MIME type (from `mimeDetector.ts`) |
| `fileSize` | `integer` | No | — | Bytes |
| `storagePath` | `text` | No | UNIQUE | UUID filename on disk (relative path from upload dir) |
| `uploadOrderIndex` | `integer` | No | DEFAULT 0 | Display order; 0-based |
| `uploadedAt` | `integer` | No | Unix epoch ms | — |

**Indexes**:
- `idx_draft_attachments_draft_id` on `(draft_id)`

**Constraints**:
- Same MIME type allowlist as `attachments` (`ALLOWED_MIME_TYPES` from `constants.ts`)
- Same per-file size limit: ≤ 10 MB (`FILE_SIZE_LIMIT`)
- Maximum 3 attachments per draft (`MAX_ATTACHMENTS_PER_IDEA` constant, spec A-005)
- `storagePath` is globally unique across both `attachments` and `draft_attachments` (same filesystem, UUID-named files)

## Modified Entities

No existing tables are modified. The `ideas`, `attachments`, and `idea_category_data` tables remain unchanged.

## Entity Relationships

```
users (1) ──────────────────── (*) drafts
                                      │
                        (0..1) ───────┤ draft_category_data
                                      │
                        (0..3) ───────┘ draft_attachments
                                              │
                                    data/uploads/ (filesystem)
                                    [shared with idea attachments]
```

On **draft submission** (atomic transaction):
```
drafts          ──(delete)──►  [removed]
draft_category_data ──(delete)──►  [removed]
draft_attachments   ──(move DB row)──►  attachments  (file stays on disk)
                                   ──(insert)──►   ideas + idea_category_data
```

---

## State Transitions

```
[form open]
     │
     ▼
  DRAFT ──── save ────► DRAFT (version++)
     │
     ├──── submit ────► [validation fails] → stays DRAFT
     │
     └──── submit ────► [validation passes]
                              │
                              ▼
                            IDEA (submitted)   +   DRAFT deleted
```

---

## Validation Rules

| Field | Rule | Error Message |
|-------|------|---------------|
| `title` | max 200 chars when provided | "Title must be 200 characters or fewer" |
| `description` | max 2000 chars when provided | "Description must be 2,000 characters or fewer" |
| `category` | must be a valid `idea_categories.slug` when provided | "Invalid category" |
| Category-specific fields | same rules as Phase 2 (`ideaValidator.ts`) | (per-field messages) |
| Attachments | same rules as Phase 3 (`attachmentValidator.ts`) | (per-file messages) |
| Draft count | max 10 per submitter on creation | "Draft limit reached. Delete a draft to create a new one." |
| Version on save | must match stored version | `{ conflict: true }` — handled separately from field errors |

**On submission only** (not on save):
- `title` is required and non-empty
- `description` is required and non-empty
- `category` is required

## Drizzle Schema Additions (`src/lib/db/schema.ts`)

```typescript
// ── Drafts ────────────────────────────────────────────────────────────────────

export const drafts = sqliteTable(
  'drafts',
  {
    id:          text('id').primaryKey(),
    submitterId: text('submitter_id').notNull().references(() => users.id),
    title:       text('title'),
    description: text('description'),
    category:    text('category'),
    version:     integer('version').notNull().default(1),
    createdAt:   integer('created_at').notNull(),
    updatedAt:   integer('updated_at').notNull(),
  },
  (table) => [
    index('idx_drafts_submitter_id').on(table.submitterId),
    index('idx_drafts_updated_at').on(sql`${table.updatedAt} DESC`),
  ]
);

// ── Draft Category Data ───────────────────────────────────────────────────────

export const draftCategoryData = sqliteTable('draft_category_data', {
  draftId:   text('draft_id').primaryKey().references(() => drafts.id, { onDelete: 'cascade' }),
  category:  text('category').notNull(),
  fields:    text('fields', { mode: 'json' }).$type<Record<string, string | null>>().notNull(),
  createdAt: integer('created_at').notNull(),
});

// ── Draft Attachments ─────────────────────────────────────────────────────────

export const draftAttachments = sqliteTable(
  'draft_attachments',
  {
    id:               text('id').primaryKey(),
    draftId:          text('draft_id').notNull().references(() => drafts.id, { onDelete: 'cascade' }),
    fileName:         text('file_name').notNull(),
    fileType:         text('file_type').notNull(),
    fileSize:         integer('file_size').notNull(),
    storagePath:      text('storage_path').notNull().unique(),
    uploadOrderIndex: integer('upload_order_index').notNull().default(0),
    uploadedAt:       integer('uploaded_at').notNull(),
  },
  (table) => [index('idx_draft_attachments_draft_id').on(table.draftId)]
);

// ── TypeScript types (additions) ──────────────────────────────────────────────

export type Draft            = typeof drafts.$inferSelect;
export type NewDraft         = typeof drafts.$inferInsert;
export type DraftCategoryData    = typeof draftCategoryData.$inferSelect;
export type NewDraftCategoryData = typeof draftCategoryData.$inferInsert;
export type DraftAttachment      = typeof draftAttachments.$inferSelect;
export type NewDraftAttachment   = typeof draftAttachments.$inferInsert;
```
